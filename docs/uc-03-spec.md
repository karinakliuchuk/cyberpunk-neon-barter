\# Текстова специфікація UC-03: Підтвердити участь у бартерній угоді

| Поле | Значення |

| \*\*Назва\*\* | Підтвердити участь у бартерній угоді |

| \*\*Актор\*\* | Учасник бартеру (Користувач) |

| \*\*Пріоритет\*\* | Високий |

\## 2. Опис



Користувач отримує сповіщення про те, що система знайшла циклічний ланцюжок обміну (A → B → C → A), у якому він бере участь. Він має переглянути деталі пропозиції та підтвердити або відхилити свою участь. Якщо \*\*усі\*\* учасники підтвердили — угода активується. Якщо хтось відхилив або стався таймаут — угода скасовується, а оголошення повертаються в статус `Active`.



\## 3. Передумови (Preconditions)



\- Користувач \*\*авторизований\*\* у системі.

\- Існує `BarterDeal` зі статусом `PendingConfirmations`.

\- Користувач має запис `BarterParticipant` у цій угоді з `IsConfirmed = false`.

\- Користувач отримав сповіщення про сформований цикл.



\## 4. Післяумови (Postconditions)



\*\*Успішний сценарій:\*\*

\- `BarterParticipant.IsConfirmed = true`, `ConfirmedAt` заповнено.

\- Якщо всі учасники підтвердили → `BarterDeal.Status = Active`.

\- Оголошення учасників переведені в статус `InBarter`.

\- Всі учасники отримали сповіщення про початок обміну.

\- Подія зафіксована в `AuditLog`.



\*\*Неуспішний сценарій (відхилення/таймаут):\*\*

\- `BarterDeal.Status = Cancelled`.

\- Оголошення учасників повертаються в статус `Active`.

\- Всі учасники отримали сповіщення про скасування.

\- Подія зафіксована в `AuditLog`.



\## 5. Основний потік (Main Flow)



| # | Актор | Дія |

|---|---|---|

| 1 | Система | Надсилає користувачу сповіщення про сформований цикл обміну |

| 2 | Користувач | Відкриває сповіщення та переходить до перегляду деталей |

| 3 | Система | Відображає деталі ланцюжка: учасники, предмети, що віддаються/отримуються |

| 4 | Користувач | Обирає дію «Підтвердити» |

| 5 | Система | Фіксує згоду: `BarterParticipant.IsConfirmed = true`, `ConfirmedAt = now` |

| 6 | Система | Перевіряє, чи всі учасники підтвердили |

| 7 | Система | Якщо всі — змінює `BarterDeal.Status = Active`, надсилає сповіщення |

| 8 | Система | Логує подію в `AuditLog` |

| 9 | Система | Завершує сценарій (успіх) |



\## 6. Альтернативні потоки (Alternative Flows)



\### 6.1. Користувач відхиляє участь (A1)



| # | Актор | Дія |

|---|---|---|

| 4a | Користувач | Обирає дію «Відхилити» |

| 4b | Система | Змінює `BarterDeal.Status = Cancelled` |

| 4c | Система | Повертає всі оголошення учасників у статус `Active` |

| 4d | Система | Надсилає сповіщення про скасування всім учасникам |

| 4e | Система | Логує подію в `AuditLog` |

| 4f | Система | Завершує сценарій |



\### 6.2. Не всі учасники підтвердили (A2)



| # | Актор | Дія |

|---|---|---|

| 6a | Система | Виявляє, що не всі учасники підтвердили |

| 6b | Система | Зберігає стан `PendingConfirmations` |

| 6c | Система | Повідомляє користувача про очікування інших сторін |

| 6d | Система | Завершує сценарій (очікування) |



\### 6.3. Таймаут очікування (A3)



| # | Актор | Дія |

|---|---|---|

| 7a | Система | Виявляє, що `ExpiresAt` минув, а не всі підтвердили |

| 7b | Система | Змінює `BarterDeal.Status = Cancelled` |

| 7c | Система | Повертає оголошення в статус `Active` |

| 7d | Система | Надсилає сповіщення про скасування |

| 7e | Система | Логує подію в `AuditLog` |



\## 7. Виключні ситуації (Exceptions)



| ID | Ситуація | Реакція системи |

|---|---|---|

| E1 | Користувач не авторизований | Повернути `401 Unauthorized`, перенаправити на вхід |

| E2 | Угода вже не в стані `PendingConfirmations` | Повернути `409 Conflict` з поясненням |

| E3 | Користувач не є учасником угоди | Повернути `403 Forbidden` |

| E4 | Помилка збереження в БД | Відкат транзакції, `500 Internal Server Error`, логування |



\## 8. Критерії приймання (Acceptance Criteria)



\- \*\*AC-03.1:\*\* Після підтвердження всіма учасниками `BarterDeal.Status` змінюється на `Active`.

\- \*\*AC-03.2:\*\* При відхиленні хоча б одним учасником угода переходить у `Cancelled`, а оголошення — у `Active`.

\- \*\*AC-03.3:\*\* При таймауті угода автоматично скасовується.

\- \*\*AC-03.4:\*\* Всі зміни станів фіксуються в `AuditLog`.

\- \*\*AC-03.5:\*\* Всі учасники отримують сповіщення про результат.
