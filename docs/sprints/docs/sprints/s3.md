## Мета спринту

Безпечно відрефакторити клієнтську частину: прибрати дублювання коду та зменшити
зв'язність між UI і логікою взаємодії з сервером. Після цього додати нову
користувацьку можливість і зафіксувати стабільну базову лінію v2.0.0.

## Що перевірено (QA)

- Characterization-тести покривають: `/health`; відмову створення без токена;
  успішне створення; читання за Id (поля `quantity`, `description`); наявність
  оголошення у списку; відмову при `quantity = 0`; 404 для неіснуючого Id.
- Після рефакторингу тести запущено повторно, зовнішня поведінка API не змінилася.
- Фільтрацію перевірено вручну: [вкажіть, наприклад, вибір кожної категорії,
  пункт «Усі категорії», порожній результат].

## Рішення та компроміси

- Фасад по-різному обробляє помилки: `login` і `getOffers` кидають `Error`, а
  `createOffer` повертає `{ ok, status, data | text }`, щоб UI показував
  бізнес-помилку 400 окремо.
- Фільтрація виконується на клієнті, без додаткових запитів до сервера.

## Відомі обмеження та технічний борг

- JWT зберігається лише в пам'яті, refresh-логіки немає.
- Фільтрація на клієнті замість серверної (`OfferFilterDto`).
- `UserId` передається в тілі запиту, а не з JWT-claims.
